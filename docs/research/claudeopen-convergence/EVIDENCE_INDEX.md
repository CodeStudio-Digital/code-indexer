## Protocolo de revalidação

1. Extrair novamente todas as citações canônicas dos Markdown.
2. Confirmar que cada path existe sob o source root indicado.
3. Confirmar `1 <= start <= end <= total_lines`.
4. Reabrir amostras por tema e verificar que o range sustenta a claim, não apenas contém o termo buscado.
5. Revalidar links relativos e a cobertura do [README](./README.md).
6. Marcar documentação histórica como `LEGACY_DOC` quando o código atual resolver uma lacuna anterior.
7. Atualizar baseline, contagens e este índice quando as fontes ou os documentos mudarem.

## Limites

- Validade de range não prova sozinha validade semântica; a revisão temática continua necessária.
- `ABSENT_FROM_SNAPSHOT` significa não observável no corpus, não inexistência no produto.
- Linhas de bundles desminificados podem sofrer drift entre versões; sempre preservar a versão 2.1.215 na claim.
- Paths externos são exibidos como texto canônico porque esta pasta pertence ao repositório CodeStudio e o corpus `claudeopen/` é somente leitura.
