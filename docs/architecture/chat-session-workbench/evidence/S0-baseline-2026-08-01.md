### Ownership de dados preservado

| Dado | Owner autoritativo | Regra para a refatoração |
|---|---|---|
| Sessão e records | bundle filesystem / `FsSessionStore` | o read model somente projeta; não cria outra autoridade |
| Runtime events | journal/JSONL da sessão | backfill e live compartilham schema e cursor |
| Estado vivo | worker pool/bus por `sessionId` | não migrar para componente ou SQLite |
| Skills, tools e providers | catálogos globais existentes | workbench agrega capabilities e metadata |
| Preferências visuais | camada de preferência do dashboard/app | nenhuma migration SQLite de sessão |

```powershell

  apps/dashboard/e2e/global-session-workbench.spec.ts --reporter=line
```

segundo attach para A e força reload com cursor/sessão para provar reattach.

## 5. Rede e render do workbench legado

O harness `session-workbench.baseline.spec.ts` usa o hook de commits do React,
mede responses `/api`, bloqueia qualquer request mutável e injeta um burst
sintético de 500 eventos somente no store frontend do Worker Log.

Comando:

```powershell
$env:CODESTUDIO_E2E_URL='http://127.0.0.1:7317'
npx playwright test --config apps/dashboard/playwright.config.ts `
  apps/dashboard/e2e/session-workbench.baseline.spec.ts `
  --project=1440x900-dark --reporter=line
```

Medição final representativa:

| Fase | Requests API | Bytes concluídos | Commits React | Mutation records |
|---|---:|---:|---:|---:|
| Lista global | 8 | 345.411 | 16 | 16 |
| Abrir sessão | 23 | 1.608.345 | 33 | 159 |
| Estado da sessão | 2 | 370 | 13 | 23 |

Achados objetivos:

- abertura duplica a leitura `?tail=40&detail=preview` e consulta `tasks` cinco
  vezes;
- `GET /api/admin/skills` responde aproximadamente 979 kB na abertura;
- Configuração busca mais aproximadamente 984 kB ao abrir;
- toda troca de destino repete `chapters?limit=1`, pois o efeito do rail depende
  de `activePanelId`;
- Worker Log fechado permaneceu isolado no burst; aberto produziu 10 commits;
- bodies de SSE não entram no total de bytes acima;
- POSTs de telemetria `renderer-freezes` foram observados e bloqueados pelo
  harness; nenhum comando ou dado de sessão foi mutado;
- não houve `pageerror`.
