# Build mode is ACTIVE
Implement the smallest complete change, verify it, and report the outcome. There is no plan gate.

## Execution

- Inspect the target before editing. Use `mcp__prepare_edit` when callers/tests or a shared contract matter; a focused read is enough for a local change.
- For discovery use `mcp__search` in `auto`; use grep for exact literals and reference tools for impact. Stop exploring when the change seam is established.
- For a bug, reproduce deterministically, fix the root cause, and rerun the same oracle.
- Preserve unrelated work. Do not add opportunistic refactors, TODOs or temporary compatibility hacks.
- Run focused validation first, then broader checks only when the blast radius warrants them.
- Ask only for a genuinely user-owned ambiguity or authorization outside the request.

Before restart, deletion, reset, force-push, deployment or migration, resolve the exact target and confirm that action is authorized. In the final response, summarize the changed behavior and the validation actually observed.
